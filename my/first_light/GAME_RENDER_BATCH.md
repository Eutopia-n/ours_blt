# 游戏批量绘制接入

游戏现在使用已有的通用批量命令、同型位置列表和纹理缓存/背景行预读。
修改位于原工程的 `software/game_view.h` 和 `software/game_batch.h`；本轮未修改 RTL。

## 提交与顺序

每帧先绘制原 HUD，再批量恢复后台页的脏块背景。背景提交完成后，依原顺序
加入魔法弹、宝石/爱心、敌人、法球和人物。全部 GPU 写响应结束后，CPU 才绘制
血条、更新计数及捕获暂停画面，最后换页。怪物层允许同纹理的命令越过不重叠的矩形，重叠像素保持原顺序。

混合素材使用32字节命令，512条满后等待完成并继续，不丢弃尾部对象。
连续至少8个相同方形纹理且尺寸/Alpha/键色开关一致时，转为4字节位置列表；
4096个位置满后同样分批。短序列继续留在混合列表，避免过多小提交。
旧能力位设备使用通用批量；无批量能力时仍可运行原单次绘制及 CPU 魔法弹路径。

魔法弹由 GPU 颜色键绘制，普通弹5×5、穿透弹7×7的原亮边与白色中心逐像素保留。
使用16×16透明填充纹理以复用已有纹理缓存和跨度跳过；右边界不足16像素时回退
裁剪后的混合命令。实际占用范围、屏外判断和边界贴合方式不变。

怪物达到16只时，在每组最多16条指令内合并未裁边、纹理及透明度相同的24×24或32×32怪物。
每组至少两只才使用相同的缓存纹理。24×24直接复用已有图集，32×32复用已有紧排图集。
靠边和无法配对的不透明怪物沿用裁剪矩形。半透明素材继续使用4/16/24/32的紧排纹理，
走已有缓存与下一行背景预读路径。透明边距和命令合并不改变像素或HUD同屏计数。

## DDR 复用

46帧图集在 `ASSET_BASE+0x4000 .. +0x1b000`。初始化时将LZ4游程展开到复用的菜单暂存区，再生成像素图集。
紧随其后的 `+0x1b000 .. +0x1c680` 存放48×48的三角冰径和24×24的圆形诱饵，末地址不包含在内。
补充图集在 `+0x8c000 .. +0xa3000`，普通弹、穿透弹和统领金弹纹理在 `+0xa3000 .. +0xa3600`。
从 `+0xa3600` 开始放置24×24和40×40怪物图集，启动时从原图集生成，共43520字节。
生成后按紧裁剪矩形提交通用批量命令。32×32怪物继续使用原图集。
霜晶史莱姆与暮晶蝙蝠固定24×24，白骨学徒与寒霜守卫固定32×32，鎏金统领固定40×40。
它们与 `+0xb0000` 开始的16KiB命令/位置暂存区分离，均位于现有1MiB素材池中。
这段补充图集与菜单捕获缓存互斥；进入游戏及暂停画面释放后重新上传图集。
列表在对应阻塞提交返回前保持只读，两个 framebuffer 的所有权沿用原流程。

游戏保留原脏块背景恢复。压测专用的融合清屏分块引擎要求固定视口和同型素材，
本轮没有把它用于混合素材游戏场景。游戏中的法球、人物和弹幕仍计为各一个精灵。
玩家魔法弹池为512，敌人池为384，另有两个统领攻击槽。
发射频率、伤害、寿命及严格30帧MAX60规则保持。每颗弹幕由20字节压缩为12字节，
仍使用Q5世界坐标和有符号速度；位移先用有符号32位计算并检查边界，再写回紧凑状态。
弹幕池从5120变为6144字节，仅多占1024字节片内RAM。

## 验证与构建

`tools/check_game_batch.py` 使用当前单次提交路径作参考，核对两页完整像素和选档规则。

- 批量+位置能力和仅通用批量两种配置共192帧，覆盖空场、满池、重叠、边界、
  受击透明、暂停/恢复、升级与结算，像素及实际绘制对象数一致。
- 三种尺寸各10帧逐像素核对图集。三种能力配置各180帧覆盖居中、四边裁剪和完全离屏。
- 五种怪物遍历1至255的最大血量，分别在满血和仅剩1点血量时核对固定尺寸。
- 当前满池案例同时绘制384只敌人、512发玩家魔法弹、遗物和统领效果，共926个同屏对象。
- 4组实际 C 生成的混合、普通弹、穿透弹及怪群命令在 RTL 中以确定性随机阻塞回放，
  同时包括冰径、护盾、诱饵及统领警告和金弹，核对完整两页像素和前台页保护。
  CPU列表构建和HDMI帧率需在板端测量。
- 加速路径的真实游戏循环再检查126帧人工负载和1899帧自然游戏，
  人工负载包含512颗魔法弹，屏内数字逐帧变化，MAX60仍拒绝超时和漏刷新窗口。
- `tools/check_bolt_capacity.py`核对满池拒绝、末尾第511槽复用及碰撞、坐标第15位
  跨越、四边越界与512条独立Q5轨迹，再运行30000次确定性游戏逻辑。

详细结果在 `reports/game_batch.json`，可逆差异在 `reports/game_batch.patch`。
最终 FPGA 编译四阶段通过，150 MHz建立/保持裕量为+0.094/+0.027 ns；
逻辑33069/60800、RAM256/256、DSP44/160。图像复制页截图占用新增的素材 ROM 容量。
固件 text106224、data36、bss19772字节，保留4KiB栈后余944字节。
全部静态 C 栈帧的保守总和为4096字节。翻书网格和游戏状态分时复用片上内存。

以上是主机像素对照、RTL仿真和编译结果，尚未烧录板卡。
下载更新后的原路径 BIT/HEX 后，应对比游戏完整帧耗时、漏刷新次数和 MAX60。
