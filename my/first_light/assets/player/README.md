# 玩家人物资源

人物使用用户提供的蓝色兜帽像素图，原图保存在 `source.png`。按图中朝向，将四行依次解释为朝下（正面）、朝左、朝右、朝上（背面），每行保留四个动作帧。这是根据图片作出的方向约定；后续可以在游戏中调整播放顺序和帧率。

| 文件 | 内容 |
|---|---|
| `source.png` | 附件原图，保持原文件内容 |
| `walk_32.png` | 4×4 透明图集，每帧 32×32，最近邻缩放 |
| `walk_32.rgb565` | 16 帧连续存储的小端 RGB565，共 32768 字节 |
| `walk_32.json` | 方向、帧索引、行距、裁切范围、源文件校验值 |
| `../../software/player_asset.h` | 当前固件使用的四个方向代表帧，调色板 + RLE，共 4624 字节（不含帧偏移表） |
| `../../sim/player_expected.hex` | 四个方向的未压缩像素参考，用于核对 RISC-V 解压和 DDR 上传 |

转换时按 Alpha ≥ 128 识别人物主体，剔除相邻格的零散杂点，等比例缩小后在 32×32 格中水平居中、底部对齐。透明像素写为 RGB565 `0x0000`，供 FPGA 的 Color Key 合成使用；不透明的纯黑像素保留为近黑 `0x0001`，防止被误判为透明。

当前菜单显示正面代表帧，保留四个方向各自的第一帧地址。游戏已接入全部 16 帧，在 DDR `0x01204000` 开始连续存储；按住板上方向键决定位置/朝向，逻辑计时选择走路帧。游戏共享调色板和压缩数据见 `software/game_assets.h`。

| 固件方向编号 | 方向 | 当前 DDR 地址 | 完整图集中的代表帧索引 |
|---:|---|---|---:|
| 0 | 下 / 正面 | `0x01200800` | 0 |
| 1 | 左 | `0x01201000` | 4 |
| 2 | 右 | `0x01201800` | 8 |
| 3 | 上 / 背面 | `0x01202000` | 12 |

每帧 2048 字节、每行 64 字节。完整图集的帧索引为 `direction * 4 + walk_frame`，文件内偏移为 `frame_index * 2048`，游戏 DDR 地址为 `0x01204000 + frame_index*2048`。RISC-V 计算位置和碰撞，FPGA 从对应帧地址读取并合成。64/128/256 性能 Sprite 仍使用独立测试图片。

上一版先接入四帧，是因为当时启动固件仅有 16 KiB 片内 RAM。本次游戏将片内 RAM 扩为 64 KiB，使用压缩图集启动解码，实现完整 16 帧动画。当前不依赖 Flash 中已有数据，也未执行 Flash 编程。用户提供的人物原图没有被本工程重新授予开源许可。

重新生成资源需要安装 Pillow 的 Python 环境，在工程目录运行：

```powershell
python tools/prepare_player_assets.py
python tools/prepare_game_assets.py
python tools/build.py firmware
python tools/build.py sim-soc --ui-smoke
python tools/build.py compile
```

普通编译不需要 Pillow，也不需要访问原先的 QQ 文件路径，已生成资源随工程保存。
