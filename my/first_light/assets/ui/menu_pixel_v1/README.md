# 像素风菜单美术资源 v1

本套资源适配 Ti60 RISC-V + FPGA 2D 图形项目的 **640×480、RGB565、Color Key=0** 绘制路径。包含 25 个可复用组件、三个菜单各三种选中状态的 9 张效果预览，以及 3 张不含文字的美术层预览。

本次交付是美术资源与接入规格。`software/main.c`、现有菜单事件处理、RTL、引脚和时序约束均未修改，启动项目仍会显示原菜单。

## 设计

- 新绘制组件使用 2×2 像素网格，硬边、切角、阶梯轮廓，不使用抗锯齿、模糊或半透明边缘。
- 深蓝面板配青色选中框，暖金色用于编号与光标。图集实际使用 21 种不透明 RGB565 颜色与 1 个透明键。
- 图标分别对应基础演示、高阶演示、幸存者、矩形填充、图像复制、双缓冲、颜色键、透明混合和 Sprite 压力测试。
- 文字与底图分离；标题、描述、按键名称可以继续由现有点阵字体绘制。
- 菜单保留三个入口、两个三项子菜单与 W/S/Enter/A 操作方式。

## 组件规格

| 组件名 | 尺寸 | 用法 |
|---|---|---|
| `background_tile`、`grid_tile` | 32×32 | 平铺背景，可选择较安静的底纹或网格底纹 |
| `panel_normal` | 24×24 | 普通菜单卡片，九宫格拼接，边距 8 像素 |
| `panel_selected` | 24×24 | 当前选中项，九宫格拼接，边距 8 像素 |
| `panel_pressed` | 24×24 | 按下状态，九宫格拼接，边距 8 像素 |
| `panel_disabled` | 24×24 | 禁用或次要提示区，九宫格拼接，边距 8 像素 |
| `header_panel` | 32×32 | 标题面板，九宫格拼接，边距 12 像素 |
| `icon_well` | 24×24 | 图标底座，九宫格拼接，边距 8 像素 |
| `keycap_normal`、`keycap_pressed` | 24×24 | 空白按键框，九宫格拼接；宽度随 W/S/ENTER 等文字调整 |
| `icon_*` | 32×32 | 九个独立功能图标 |
| `chip_emblem` | 48×48 | 原创像素芯片徽记 |
| `cursor_0`～`cursor_3` | 16×24 | 四帧选择光标，静态菜单可只使用第 0 帧 |
| `separator_tile` | 32×8 | 横向分隔线平铺块 |

九宫格是将小图分成九块：四角保持尺寸，四边与中心重复填充。这样同一张 24×24 图片可以组成 576×68 卡片，保持像素边缘清楚，减少存储。所有边距已使用输出图片中的像素单位，无需再乘 2。

不要对这些图片使用双线性缩放；需要放大时使用整数倍最近邻。拼接目标的宽、高采用偶数，保持新美术的像素网格。

## 项目接入

### 1. 选择存储方式

整图集解码后占用 **128 KiB DDR**。压缩 C 数据为 **7,036 字节**：RLE 6,742 字节、调色板 44 字节、25 个描述符合计 250 字节。这个数字不含后续新增绘制代码、链接对齐和栈开销。

现有资源池 `ASSET_BYTES` 为 1 MiB。接入时需要为 UI 分配经过核对的空闲区，并在固件编译后重新查看程序 RAM 的剩余空间。本套资源只记录图集内偏移，**没有分配或写入任何新的绝对 DDR 地址**。

可以使用整图集，也可以只选择需要的独立资源；不要同时上传两份相同的像素数据。

### 2. 解码数据

`menu_ui_assets.h` 中每个 16 位 RLE token 的格式为：

```c
uint32_t run_length = token >> 5;       /* 1～2047 个连续像素 */
uint32_t palette_index = token & 31u;   /* 调色板索引 */
uint16_t pixel = menu_ui_palette[palette_index];
```

按顺序展开，应得到 `256×256` 个像素。`menu_ui_rle.bin` 只是压缩资源数据，不能当成 `.bit` 或 Flash 下载文件使用。

### 3. 绘制图集区域

已有 `blend_image()` 可以绘制带透明键的组件。`ui_base` 应由后续接入代码在核对资源地址后提供，下面仅展示图集偏移和已有驱动的正确参数：

```c
const MenuUiRect *r = &menu_ui_rects[MENU_UI_ICON_COPY];
uint32_t source = ui_base + (uint32_t)r->y * 512u + (uint32_t)r->x * 2u;

int result = blend_image(source, 512u, dst_x, dst_y,
                         r->w, r->h, 255u, 0u, GFX_BLEND_KEY);
```

图集子图即使只有 32 像素宽，源行距也仍是 **512 字节**。如果使用独立 `rgb565/icon_copy.rgb565`，行距才是 `32×2=64` 字节。

透明位置写为 RGB565 `0x0000`；不透明深色至少为 `0x0001`，避免被颜色键消除。图集含透明角和留白，绘制这些区域时应开启颜色键。

### 4. 文字与布局

效果图直接复用项目的 `font_cn.h` 和 `font5x7.h` 点阵数据。正文使用现有尺寸，大标题对中文作 2 倍整数缩放、英文作 3 倍整数缩放。现有 `text_at()` 没有缩放参数，因此后续采用大标题时，需要增加一个局部整数缩放绘制函数；本次没有改动字库或文字函数。

`layout.json` 给出了 640×480 中标题区、三张卡片和底部按键提示区的位置。卡片为 `576×68`，间隔 8 像素，标题和图标与当前的三项导航数量匹配。效果图是待接入的布局建议，并非已经运行在 FPGA 上的截图。

## 重新生成

在 `my/first_light` 下执行：

```powershell
python tools/prepare_menu_ui.py
```

依赖 Python 3 与 Pillow。展示板的中文说明使用本机 Windows 微软雅黑字体；真正的菜单文字使用项目点阵字库。普通 FPGA 编译不会自动执行此工具。

生成工具的主要函数：

- `sprite()`：在整数网格绘制组件并做最近邻放大。
- `nine_slice()`：保持四角，将边与中心重复拼成目标尺寸。
- `draw_text()`：用已有点阵字形绘制预览，并拒绝缺失字符。
- `encode()`：输出小端 RGB565，检查二值 Alpha 与透明键规则。
- `menu_preview()`：组合组件，展示三个菜单与不同选中状态。

## 校验与素材来源

生成时已检查图集边界、二值 Alpha、不透明像素与透明键冲突、现有中文字形覆盖和 RLE 全像素往返一致性。`manifest.json` 记录图集数据的 SHA-256。

新增 UI 组件由本工具原创逐像素绘制，没有调用 AI 绘图服务或引入外部第三方美术。效果图右上角人物复用 `assets/player/walk_32.png` 中的用户已有角色；人物与现有字体继续遵循原项目的授权，未对其重新授予许可证。
