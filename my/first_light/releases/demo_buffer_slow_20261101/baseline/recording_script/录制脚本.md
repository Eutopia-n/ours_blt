## 00:00—00:20｜项目与平台

**画面和操作**

- 板卡、按键、HDMI 显示器同框，随后切到分类菜单。
- 字幕：Ti60F225 / RISC-V + FPGA / DDR 帧缓冲 / HDMI。
- 可补充配置字幕“CPU、BitBlt 150MHz；DDR fabric 100MHz”，不要写成“DDR 全部运行在 150MHz”。

**口播**

> 这是我们基于易灵思 Ti60F225 实现的 RISC-V 与 FPGA 异构二维渲染系统。RISC-V 负责交互、游戏逻辑和命令下发，FPGA 负责位块搬运与混合，结果经 DDR 帧缓冲通过 HDMI 输出。下面按赛题要求展示基础功能、总线优化和高阶效果。

**对应要求**：整体 RISC-V＋FPGA 架构、内存图像到帧缓冲及 HDMI 输出。

## 00:20—01:00｜Solid Fill 与 CPU/FPGA 比较

**画面和操作**

1. 首页选择“基础演示”，进入“矩形填充”。默认是 CPU，LOAD=8。
2. 短按 W 两次并分别松开：8→32→64；按 D 一次换色。用事先实测合适的档位也可以，但两路要保持同档。
3. 停住参数，等 CPU 的 30 帧统计出现。
4. 按 S 切到 FPGA，等 FPGA 的 30 帧统计出现；此时两路数据和 SPEEDUP 都应有效。
5. 保持 FPGA，至少保留 2 秒完整指标画面。尚未出数时不提前切镜头。

**口播**

> 首先是纯色填充。每个方块都是由 C 驱动下发的填充任务，可以改变数量和颜色。保持负载不变，按 S 手动切换 CPU 与 FPGA，两条路径采用相同的运动序列。这里同时显示实际呈现帧率和批次填充耗时。如果两路帧率都接近显示刷新上限，仍可以通过微秒数和耗时比观察性能差异。

**字幕重点**：Solid Fill；相同负载、相同运动序列；FPS 与 FILL_US。

**对应要求**：基础 1 的纯色填充；基础 3 的屏幕 CPU/硬件帧率对比。

## 01:00—01:50｜Block Copy 与复制性能

**画面和操作**

1. A 返回基础菜单，选择“图像复制”。
2. 按 D 切一次图，展示风景与城市两个源图。停留在其中一张，后续比较期间不要再换图。
3. 短按 W 两次，将 LOAD 从 1 调到 4。画面仍是一对源图/结果，含义是每帧执行 4 次完整复制。
4. 默认 CPU，等统计出现；按 S 切 FPGA，等另一组统计出现，保持 FPGA。
5. 给两路 COPY_US、FPS 和 SPEEDUP 留清晰特写。

**口播**

> 图像复制使用两张独立存放在 DDR 中的二百五十六乘一百九十二 RGB565 图片。左侧是源图，右侧是复制结果。现在切换图片，并在相同图像、相同复制次数下比较 CPU 和 FPGA。COPY_US 是每帧全部复制任务的耗时，SPEEDUP 是两路耗时之比，MB/S 表示有效复制吞吐量；LOAD 表示每帧复制次数。

**字幕重点**：256×192；DDR 源图→后台帧缓冲；LOAD=4 是四次复制/帧。

**对应要求**：基础 1 的 Block Copy；基础 3 的 C 驱动与 CPU/硬件对比。

## 01:50—02:30｜指令字段、AXI Burst 和 FIFO

**画面和操作**

1. 保持 FPGA 路径。若上一段为 LOAD=4，短按 W 两次：4→8→1。
2. Enter 进入详情，等新的硬件统计出现。指向 OP、SRC、256×192、AR、AW。
3. LOAD=1、当前地址与步长配置下，读、写突发次数预期各为 1536；实际录制前核对，不能在未出数时直接口播“实测 1536”。
4. 插入约 5 秒当前 C 驱动屏幕录制，标出 GFX_OPERATION、GFX_SRC、GFX_DST、GFX_WIDTH、GFX_HEIGHT 和启动写入。
5. 插入约 12—15 秒实际仿真波形，放大 AWLEN、WVALID/WREADY、WLAST、FIFO occupancy、push/pop。角标“同一 RTL 的 ModelSim 仿真证据”。

**口播**

> 详情页展示操作类型、源地址和尺寸；在 C 驱动中补充展示目的地址，五项指令信息仍完整下发。加速器通过 AXI 直接访问 DDR，读写突发由硬件实际统计。这里单次复制包含九万八千三百零四字节。下面是同一 RTL 的仿真波形：AWLEN 为十五表示十六拍突发；FIFO 在下游等待时保存待传数据，在握手时出队。

**字幕重点**

- 32 位/拍，完整 16 拍突发为 64 字节。
- 本配置 LOAD=1：98,304÷64=1536 次读突发及 1536 次写突发。
- AR/AW 与等待周期属于 BitBlt 批次，排除 CPU/HUD/HDMI 流量。
- FIFO 深度 16 是配置；波形才展示其运行行为。没有“关闭 FIFO”或“1 拍/16 拍”性能对照，不口播具体优化倍数。

**对应要求**：基础 1 的五项指令；基础 2 的总线直接访问、Burst 与内部 FIFO。

## 02:30—03:00｜撕裂与双缓冲防撕裂对比

**画面和操作**

1. A 返回基础菜单，进入“双缓冲”，默认“单缓冲 撕裂”，停留约 5 秒，特写三根竖条中部的横向错位。
2. S 手动切到“双缓冲 防撕裂”，保持同一速度、同一参考线，停留约 5 秒，拍清完整竖条。
3. S 切回单缓冲，再 S 切回双缓冲，说明模式完全由按键控制；需要放大差异时 W 调到 64 像素步长。不要用亮度闪烁解释撕裂。
4. 在运动状态拍清 OUT_HZ；Enter 暂停后观察静止完整竖条，A 返回菜单并保留 2～3 秒，确认菜单稳定。

**口播**

> 进入时默认单缓冲，在显示器扫描过程中直接写前台显存，竖条上、下部分出现位置错开。现在按 S 手动切到双缓冲：后台完整绘制后，在帧边界换页，竖条保持完整。两种模式使用相同图案和速度，不会自动切换。OUT_HZ 显示实际输出刷新率，与渲染 FPS 分开。

**现场加一句，仅在画面读数支持时读**：当前显示刷新率约为六十赫兹，满足赛题最低输出要求。

**对应要求**：基础 1 的 640×480@60Hz 输出；基础 3 的双缓冲与防撕裂。MISSED 不是撕裂次数；单缓冲 SWAPS=0，WAIT_US 是同页帧边界节拍等待，并不代表双缓冲。

## 03:00—03:35｜硬件颜色键

**画面和操作**

1. 返回首页，选择“高阶演示”→“颜色键”。默认右侧开启颜色键。
2. W 关一次，让右侧透明色矩形重新出现；W 再开一次，让背景透出。
3. D 从黑色切到品红色，拍清“品红色 F81F”、左右图及去背结果。
4. S 切一次棋盘背景，给“采样像素核对 8/8”留清晰画面。

**口播**

> 颜色键页面固定使用 FPGA。左侧是完整原图，右侧按指定透明色去背。关闭颜色键时，矩形背景重新出现；打开后，匹配透明色的像素跳过写入，保留目的背景。这里支持黑色和品红色两种选择。页面还从 DDR 读回八个采样位置，核对边缘和图案结果。

**字幕重点**：Color Key；匹配透明色→跳过像素写入；Alpha 混合关闭。

**对应要求**：高阶 2 的可设透明色、跳过透明色像素、不规则精灵边缘。

## 03:35—04:20｜硬件 Alpha 混合

**画面和操作**

1. A 返回高阶菜单，选择“透明混合”。初始 T=255、前景权重=0，右侧完全显示背景。
2. 先拍初始 255，再按 Enter 两次并分别停留：0→128，依次展示完全透明、完全不透明、中间混合。
3. 短按 W 两次：128→133→138；按 D 两次回到 128，证明步长为 5。
4. S 换背景，在中间透明度下拍清棋盘从前景中透出的效果和 8/8。

**口播**

> Alpha 页面同样固定使用 FPGA，颜色键关闭。左侧是不透明参考，右侧读取前景和背景，按权重执行 RGB565 通道混合。页面显示的是透明度，硬件前景权重等于二百五十五减去透明度。透明度为零时完全不透明，为二百五十五时完全透明。W、D 每次调整五，Enter 可快速切换三个预设。

**字幕重点**：OUT=FG×A+BG×(1−A)；A=(255−T)/255；实际 RGB565 实现带整数四舍五入。

**对应要求**：高阶 1 的硬件前景/背景 Alpha 混合。口播不将“8/8”扩大为全图实板验证。

## 04:20—05:05｜Alpha＋Color Key 固定负载压测

**画面和操作**

1. A 返回，进入“SPRITE 压力”。默认 32×32、1 个 Sprite，固定 FPGA Alpha＋Color Key。
2. 长按 W 接近预先实测的数量，再用 W/S 每次 5 个微调。松手等待完整 30 帧窗口，从 WAIT 变成 PASS。
3. 在数量、尺寸、实际 FPS、PASS、MAX60 同时可见时至少停留 3 秒。
4. D 从默认 32×32 降到 24×24；完整循环为 32→24→16→4→32。每个尺寸的 MAX60 独立保留；改尺寸后要重新采样。调整到预先确认的通过数量，再保留完整窗口。
5. 若时间充裕，可展示再增加数量后的 FAIL，并降低数量恢复 PASS。若未实际出现 FAIL，不声称已经找到硬件极限。

**口播**

> 独立压力页同时开启 Alpha 和颜色键，所有运动 Sprite 都提交给硬件。我们逐步增加固定尺寸的数量，每次按键变化五个。只有连续三十帧满足完整渲染预算、并且没有漏过显示刷新，才记录这一尺寸的 MAX60。当前通过数量和帧率以屏幕实测值为准；切换尺寸后重新测量。

**可加入的实测句，录制前填好**：在【尺寸】下，本次测试达到【数量】个 Sprite，并通过连续三十帧窗口。

**对应要求**：高阶 3 中 Alpha＋Color Key 开启时的稳定 60FPS 负载挑战。独立压测是可重复测量，仍需下一段互动游戏。

## 05:05—05:50｜互动游戏综合展示

**画面和操作**

1. 压测 A 返回高阶菜单，再 A 返回首页，选择“冰霜幸存者”，Enter 打开说明，再 Enter 开始。
2. 实拍 W/S/A/D 连续移动、自动攻击和敌人追踪。需要升级时 W/S 选择、Enter 确认。
3. 可切入同一 bit 版本游戏自然运行到较密集阶段的连续原速片段，字幕“同版本游戏运行至 ×× 秒，原速实拍”，保留 HUD 时间和指标。不要把从零开始 45 秒与较后阶段拼成无说明的连续过程。
4. 特写 FPS、SPRITES、MAX60 与画面内实际活动。若要暂停退出，正常游戏中 Enter 暂停后 A 返回；升级选择页可用 D 暂停后 A 返回。

**口播**

> 最后是互动游戏。RISC-V 负责移动、碰撞、自动攻击和升级逻辑，人物、怪物及效果图像由 FPGA 执行颜色键与 Alpha 合成。这里展示持续移动、敌人追踪以及较密集场景，并保留 FPS、实际绘制元素和 MAX60 指标。游戏的元素统计包含不同绘制类型，不能直接等同于全部使用硬件 Alpha 的 Sprite 数量。

**口径备注**：敌人逻辑池上限 256、我方子弹池上限 256，不等于实拍时有 512 个同屏硬件 Sprite。游戏中部分子弹和 HUD 由 CPU 绘制。MAX60 是通过 30 帧窗口中实际绘制元素的峰值记录；不能把它读成整个游戏始终维持该数量的 60FPS。游戏未达到 60 时保留真实数据，不用独立压力页的 PASS 替换游戏结论。

**对应要求**：高阶 3 的 RISC-V 高负载互动游戏，以及真实运行性能展示。

## 录制与剪辑时保持的口径

- 基础性能比较：选好负载和图像，再测完两路；换图、换负载、切换详情视图会清空样本。切换 CPU/FPGA 本身保留同配置另一条路径的读数。
- 高阶两效果页没有 CPU/FPGA 切换。它们的 S 是换背景，不要沿用旧视频的 CPU 对照台词。
- 压测的“FIXED 60 FPS”是目标/判定预算，PASS 和真实 FPS 才是结果，不把标题当作实测证明。
- AR/AW 是突发次数，WAIT 是图形时钟周期，MB/S 是有效复制吞吐；不混为字节数、微秒或全 DDR 利用率。
- 实板画面、ModelSim 波形、宿主布局预览分别标注。本脚本只要求插入实际仿真波形，不要求使用任何宿主性能预览。
- 可剪掉找菜单和长时间调负载，但比较结果与 PASS 判定保留正常速度、清晰指标。需要读屏的段落多留原片停顿，不通过加速播放表现“更快”。
