# Enter 封面卡死修复与全屏演示排版对齐（2026-11-16）

当前工程已经修复 UI 绘制完成信号丢失的问题，并将六项演示的排版按本地 `魔法书交互预览.html` 更新。该 HTML 保留原样，上一版 `reference_ui_20261116` 的全部文件也保留原样。此目录为重新编译的下载文件，尚未上板。

## 卡在封面的原因与修复

菜单专用 FPGA 模块 `rtl/ui_compositor.v` 原先只将 DONE 拉高一个时钟。CPU 通过 APB 查询时可能漏读，于是 `wait_render()` 一直等到超时并进入失败停机。现在 DONE 保持到下一条 UI 指令被接收，CPU 延迟读取仍能确认完成。无需改按键映射或延长超时。

已先用旧模块复现：绘制结束后延迟 257 个时钟读真实 APB，状态为 `00000008`、DONE 丢失，测试失败。相同检查在修复后通过；六组真实书页指令也检查 DONE 保持。旧失败记录 `evidence/ui_done_before_fix.log` 是用于证明问题的预期失败，不代表当前版本失败。

## 六项演示的画面

- 填充、复制：CPU/FPGA 徽标、三行指标、SPEEDUP/MB/S、详情列、双图窗口、图像说明与页脚按参考定位。运行中的耗时较长时向左扩展数字，保留有效位。
- 双缓冲：模式说明、两列三行状态、视窗与两行操作说明按参考定位。默认单缓冲、STEP=8，S 切模式，真实扫描/写入行为保留。
- 颜色键、透明混合：左右实验窗、参数、采样核对、说明文字及操作提示按参考定位；核对数值来自真实结果，保留原实验图形和算法。
- 压力：三列大号 SPRITES/FPS/MAX60、SIZE、DDR 读写、全宽测试区及页脚按参考定位。仍从 1 个 Sprite 开始，五步增减、原图形和 MAX60 判定保留。未采样时显示占位符。

[六项演示实际代码预览](evidence/reference_demo_gallery.png) 来自正式 C 函数，初始占位值和测试计数用于展示布局，不是板卡性能。`evidence/demo_reference/comparison.json` 记录 16 种演示状态的像素对照：只排除实时数值和移动测试区，其余区域在 RGB565 下与本地 HTML 一致；复制图像与颜色键/Alpha 的确定性实验图也参与比较。

封面、九种菜单选择及游戏准备页继续与预设逐像素一致。游戏准备、运行、暂停、强化、失败和胜利继续使用已接入的全屏界面；场景保持纯色 `0x1085`。原人物、美术包、玩法、150 MHz 时钟、引脚和 1 MiB 素材池保留。

新增的小函数 `demo_badge()` 统一绘制参考徽标，`demo_number()` 统一绘制有宽度限制的数值，`effects_fraction()` 组合透明度文本。固件补充独立 `memset()`，供编译器生成的局部缓冲区清零使用，避免依赖外部 C 库。
