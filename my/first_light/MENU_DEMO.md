## 菜单与独立功能

上电停留在分类菜单：基础演示、高阶演示、冰霜幸存者。前两项进入后再选择具体功能；功能页一直停留，所有功能页按 A 返回；返回后保留原菜单选项。

| 分类 | 屏幕选项 | 演示内容 | 操作 |
|---|---|---|---|
| 基础 | 矩形填充 | 三个不同大小的 RGB565 彩色矩形 | 切换颜色组合 |
| 基础 | 图像复制 | 左侧 128×96 源图，右侧 DDR 拷贝结果 | 改变目标位置 |
| 基础 | 双缓冲 | A/B 页标识、帧号、移动竖条；页底色交替 | 切换运动速度 |
| 基础 | 视频模式 | 色条、对齐网格、实际测量的有效分辨率 | 切换色条/网格 |
| 高阶 | 颜色键 | 左侧原始图片，右侧移除黑色背景；不启用透明混合 | 开关右侧颜色键 |
| 高阶 | 透明混合 | 左侧不透明参考，右侧按比例混色；两侧均关闭颜色键 | W 加一；D 减一；支持长按，0～255 饱和；A 返回 |
| 高阶 | Sprite 压力 | FPGA 开启 Alpha + Color Key，从 1 个开始逐个增减同屏运动 Sprite；每档采样 30 帧，完整渲染不超过 16.6667 ms 且逐帧无漏刷新才记录最高数量 | W 加 1；S 减 1；W/S 长按连发；D 换尺寸；A 返回 |

压力页默认 24×24、1 个 Sprite。按 D 按 4×4 → 16×16 → 24×24 → 32×32 循环切换尺寸。切换尺寸保留当前数量，重新采样，但保留各尺寸本次进入压力页以来的独立 `MAX60`；数量最低为 1。按 A 返回功能菜单。

每页只突出一个功能；各页共用 HDMI 输出、双缓冲和文字 HUD。“独立”指可以单独选择、观察和操作，显示所必需的公共模块继续工作。菜单顶部还显示玩家预览，人物来自附件像素图。

字体使用 ASCII 5×7 与 Fusion Pixel 12px 简体中文点阵，中文字形放在 14×14 像素字符单元中。菜单使用无外框的深蓝底色和简洁卡片，首页三张卡片进入基础、高阶及游戏；子菜单列出 4 项基础功能或 3 项高阶功能。当前选项用蓝色卡片与青色左侧标记突出。按键说明固定在底部。功能键统一命名为 W/S/A/D/Enter；所有演示页和游戏菜单页均使用 A 返回，游戏进行中 A 仍控制人物左移。游戏人物由 J28 外接的四个方向键控制。

Alpha 初值为 128。短按 W 增加 1，短按 D 减少 1；持续按住约 300 ms 后，每约 120 ms 再调一级，松开停止，A 返回功能菜单。Sprite 压力页固定使用 FPGA Alpha + Color Key；W/S 调节负载，D 循环切换 4×4、16×16、24×24、32×32 素材，A 返回，不提供 CPU 路径。使用 100 MHz CLINT 计时，实际更新时间以主循环帧边界为准。到达 0/255 后保持，不会跨越端点突然跳变。

评委演示时先选择透明混合：画面显示参考不透明图、FPGA 透明度及 0～255 数值，再按 S 切换软件/硬件。顶部显示两路帧率、`RENDER_US`、`DDR_RD/WR` 和实测输出尺寸；黄色标记当前渲染路径。Sprite 压力页固定启用 FPGA Alpha + Color Key，提供 4×4、16×16、24×24、32×32 四种完整素材；每档连续采样 30 帧，并显示该尺寸的 `MAX60` 固定 60 FPS 帧预算下最高通过数量；W 增加 1 个 Sprite、S 减少 1 个，D 循环切换尺寸，A 返回，不设置档位表上限。

颜色键与透明混合分开演示的原因：去除黑色背景和按比例混色是两个不同操作，分开后可以直接辨认效果。透明度为 0 时右侧完全显示背景，透明度为 255 时与左侧不透明参考一致，中间值可看到背景透过图片。

## 按键

按键为 J28 外接五键，低电平有效；复位键不变。

| 按键 | 分类/功能菜单 | 功能页 |
|---|---|---|
| W | 上一项，支持循环 | 压力页数量加 1；Alpha 增加透明度；游戏上移 |
| S | 下一项，支持循环 | 压力页数量减 1；普通页切换软件/硬件；游戏下移 |
| A | 子菜单返回首页 | 返回功能菜单；游戏菜单页返回首页；游戏进行中左移 |
| D | — | Alpha 减少透明度；压力页循环换尺寸；普通页调整参数；游戏右移 |
| Enter | 进入所选分类或功能 | 游戏开始/暂停；升级确认 |

前 6 个功能默认使用硬件并固定显示该功能。Sprite 压力页固定使用 FPGA 硬件合成；顶部显示当前负载的帧率、渲染时间、DDR 读写 burst 和最高稳定负载。

按下和松开各保持至少 30 ms。单次按下只产生一次事件，长按不会连续改变菜单选择；Alpha 和 Sprite 压力页的长按由软件专门处理。压力页 W/S 首次立即加/减 1，持续约 300 ms 后，每约 60 ms 再变化 1 个；实际响应以帧边界为准。松开停止，同时按 W/S 抵消，数量不会低于 1 或整数回绕。D 只切换一次尺寸。每次负载变化重开 30 帧采样窗口，长按调整过程中显示 WAIT，松开并保持负载约半秒后才能形成有效的 MAX60 判定。UART 只输出诊断与测量日志。

界面文字绘制增加字段宽度及 640×480 边界保护，数字字段超出容量时用 `9999+` 一类标记表示溢出，UART 保留完整数值。普通功能页将 DDR_RD/DDR_WR 分行，调整 RISC-V FPS 数值及 Alpha `/255` 间距；游戏将 SPRITES、MAX60、FPS 分配独立栏位。检查工具 `tools/check_ui.py --cc <本机C编译器路径>` 使用固件实际字体和布局函数进行主机检查，生成的 `reports/ui_check_*.png` 是文字布局预览，不是 RTL 仿真或实板截图。

## 指标口径

- 普通功能每 4 帧形成一组统计；Sprite 压力页每 30 帧形成一组。FPS 按实际呈现间隔计算，包含文字绘制、换页等待和 UART 报告开销；报告后保留上一呈现时间戳。
- RENDER_US：普通功能页仍统计场景（不含 HUD）；压力页统计场景、坐标计算及 HUD 更新的完整渲染平均微秒数，不包括换页等待。压力页 UART 的 `MAX_US` 是窗口内单帧最长完整渲染时间，`MISSED` 是漏过的显示刷新次数。
- SPRITES：压力页为本档提交给硬件合成器的图片数；Color Key / Alpha 页各绘制 8 个固定图片；其余功能页为 0，不再附带移动 Sprite 负载。
- 屏幕 `DDR_RD/DDR_WR`：渲染引擎每帧平均读/写 burst 数，整数向下取整；UART `DDR_AR/DDR_AW` 是一组普通页 4 帧、压力页 30 帧的总数。普通页显示 `RISC-V FPS / FPGA FPS`，供 CPU 参考路径和 FPGA 合成路径比较。
- CPU 路径的渲染器计数为 0，**不表示 CPU 没有访问 DDR**。这些计数排除 CPU、HUD 和 HDMI 扫描流量，不是 DDR 控制器全局流量。
- 改变功能参数或 Sprite 数量会清空旧样本；普通页切换软件/硬件会重开采样窗口。压力页只跑 FPGA，不存在 CPU 对照读数。每帧还核对 `GFX_FRAME_COUNT`（`0x6C`）增量为 1，并检查完整渲染周期数不超过 1,666,667；不再根据有轮询抖动的换页返回时间戳直接判定单帧通过。
- 640X480 来自实际 DE/HS/VS 测量寄存器；该页面不切换 HDMI 输出分辨率。
- 随机运动采用可复现的初始相位、速度与方向，边界连续反弹；软件/硬件 从相同帧序列开始，便于比较。

## 存储与复现

板卡的 8 MB Flash 与 256 MB DDR3 是外部存储。A/B framebuffer 共 1,228,800 字节，独立图片资源池从 0x01200000 开始。原测试/菜单图像及四档压力素材共 13984 字节；游戏图集额外 51200 字节，启动总上传 65184 字节。首次进入游戏还会生成一张 614400 字节背景并复用。

程序运行在本次扩为 64 KiB 的片内 RAM 中，链接脚本保留至少 4 KiB 栈。固件随 bitstream 启动；要掉电保留，须按 `FLASH_PROGRAMMING.md` 将 bitstream 一次性写入 SPI Flash。

在仓库根目录执行：

```powershell
python my/first_light/tools/build.py firmware
python my/first_light/tools/build.py sim-soc --ui-smoke
python my/first_light/tools/build.py compile
```

联合仿真仅缩短按键消抖等待以减少运行时间；实际工程仍为 100 MHz 下 20 ms 消抖。

下载后应先看到分类菜单，再看到包含 4 项功能的子菜单；若仍显示旧动画，确认下载的是重新生成的 `outflow/first_light.bit`。若按键无响应，查看 `button_input.pending` 和 GPIO `button_ack[0]`。若无画面，先查 DDR `cal_done`、HDMI PLL `hdmi_tx_locked`，再看 UART 是否有 `FAIL` 或 `TRAP`。实际显示器观感及实板性能仍需上板验收。
