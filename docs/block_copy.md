# Block Copy 最小里程碑

## 模块职责

`blt_block_copy` 接收一次矩形复制命令，从源矩形逐像素读取数据，再写入目标
矩形。当前实现以正确性为先，一次只保留一个未完成读请求，不直接实现 AXI
Burst，也不包含跨时钟逻辑。

## 接口与握手

- `clk`：唯一时钟。
- `rst`：同步、高有效复位。
- `start && cmd_ready`：接收源/目的地址、跨度和宽高。
- `rd_valid && rd_ready`：下游接收一个读地址。
- `rd_data_valid && rd_data_ready`：模块接收对应的有序读数据。
- `wr_valid && wr_ready`：下游接收一个写地址和像素。
- `wr_last`：本条复制命令的最后一个写请求。
- `done`：命令结束脉冲。
- `invalid_cmd`：宽或高为 0 时的结束标志；此时无读写请求。

读请求必须按顺序返回；当前最多一个请求未完成，因此不需要读 ID。请求通道
受阻时地址保持稳定，写通道受阻时地址、数据及 `wr_last` 保持稳定。

## 地址规则

地址均为字节地址，当前每像素 4 字节。行内地址递增 4；换行时分别使用
`src_stride_bytes` 和 `dst_stride_bytes` 计算下一行起始地址。

当前版本不保证源、目标区域重叠时的 memmove 语义；集成前应由软件禁止重叠，
或者后续增加反向复制模式。

## 验证点

1. 3x2 正常复制，源和目标使用不同的行跨度。
2. 1x1 边界复制。
3. 高度为 0 的空操作，无读写请求。
4. 读请求和写请求分别遭遇多周期背压，数据不丢失且请求保持稳定。

## Efinity

打开 `efinity/blt_block_copy.xml` 后只运行 Synthesis。工程目标是
`Ti60F225/I3`，顶层为 `blt_block_copy`。没有真实 Peripheral/SDC，不使用
该独立工程生成的 bitstream 上板。
